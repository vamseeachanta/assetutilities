Read-only branch hygiene report

This command inventories branches for maintainer review without changing Git state or contacting a remote. It supports the reporting portion of issue 19. The issue's supersession assessment favors PR-based integration. Consequently, monthly naming is optional and no branch is deleted, created or merged.

Run

From the repository root, with Python 3.9 or later and Git on PATH:

python scripts/git/branch_hygiene.py --base origin/main
bash scripts/branch-hygiene.sh --base origin/main
python scripts/git/branch_hygiene.py --base main --month 202601 --fail-on-findings

--repo selects a repository; the default is the current directory. The Git Bash wrapper accepts the same arguments and uses PYTHON to select an interpreter when supplied. Output is JSON on stdout. Errors are generic on stderr to avoid exposing Git diagnostics or environment details.

ExitMeaning
0Report generated; default even when review candidates exist.
1With --fail-on-findings, at least one merged_review branch exists.
2Invalid arguments or inspection failure; no usable report.
Command exit contract. Monthly annotations do not change exit status.

Method and worked example

Inputs: an integration branch main with commit chain A → B, topic/done pointing at A, and current branch topic/open pointing at C, where C descends from B. The integration base is B. Reachability from B contains A and B, but not C. Thus the independently calculated merged set is {main, topic/done}. Protection and current-branch rules are applied next.

Input refAnswerReason
refs/heads/mainprotectedIntegration base and conventional main branch.
refs/heads/topic/donemerged_reviewA is reachable from B; candidate for human review only.
refs/heads/topic/opencurrentCurrent branch is preserved irrespective of reachability.
Hand-derived worked example, also encoded in the regression tests.

Other unreachable branches report unmerged. Both main and master are protected, as is an explicitly named base ref. Symbolic remote HEAD refs are omitted. Detached HEAD is reported as JSON null. The base commit is resolved once and included in the report.

Optional monthly example: for input 202601, the retained names are 202601 and 202512. Calendar subtraction gives December of the preceding year. A branch named 202401 is annotated outside_window; topic/open is not_monthly. An unmerged branch remains unmerged even outside the monthly window. Dates and branch names in this example are illustrative inputs, not engineering constants.

Daily use and limitations

A maintainer may invoke the report from an existing authorized daily job and retain stdout according to repository policy. This change installs no schedule and sends no notifications. Reports contain branch names and commit identifiers; review them before sharing.

Remote refs are locally cached observations, explicitly marked local_cache_only. Fresh remote state is not established by this command. It does not fetch. Ref enumeration is not an atomic snapshot: concurrent changes can invalidate classifications. It does not enumerate other worktrees, PR state or branch protection. No output authorizes deletion. Revalidate current state and obtain applicable approval before any Git mutation.

Git child processes discard inherited GIT_* overrides, preserve normal Git configuration, capture output and suppress extra Windows console windows. The command is a reporting utility, not a sandbox for an untrusted Git installation.
