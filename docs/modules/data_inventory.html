Data consolidation inventory

Summary

assetutilities.data_inventory provides a read-only inventory of regular files below an explicitly selected directory. Logical byte totals, relative paths and optional SHA-256 duplicate-content candidates support consolidation planning. The utility does not select a canonical copy or perform data migration.

Inputs and interface

The input is an existing directory with permission to enumerate its entries. The directory itself shall not be a symbolic link. The optional hash_contents=True argument reads file contents; the default reads metadata only. The module uses the Python standard library.

from assetutilities.data_inventory import inventory

report = inventory("example-input", hash_contents=True)
print(report["logical_bytes"])

The command-line interface emits JSON on standard output. Store redirected output outside the directory being scanned so that it does not become input.

python -m assetutilities.data_inventory example-input --hash > inventory.json

For a source checkout, set PYTHONPATH=src before the command. Output paths are relative to the input root; the absolute root is omitted. Relative names can still identify sensitive data, so inventory publication requires review.

Method

Python's os.walk enumerates the directory without following symbolic links. Regular files are identified using their link-independent metadata. Symbolic links and special files are listed in skipped; empty directories have no file record. Hidden regular files are included. There is no implicit exclusion for caches, repositories, large files or nested mount points.

The logical byte total is B = sum(s_i), where s_i is each regular-file path's st_size in bytes. The file count is the number of recorded regular-file paths. These definitions use Python 3.11 documentation, first released in 2022; no engineering coefficients or acceptance limits are introduced.

With hashing enabled, hashlib.sha256 is updated from bounded buffers. Files with equal byte lengths and SHA-256 digests are grouped as candidates. Members and file records are sorted by relative path. These are digest matches, not byte-by-byte identity checks. The published reference vector is the first input/output in the NIST SHA-256 example (undated): input abc and its stated digest.

Worked example

The following example creates only synthetic inputs. Start in a writable scratch directory and select a new directory name to preserve existing data.

from pathlib import Path
from assetutilities.data_inventory import inventory

root = Path("example-input")
root.mkdir()  # Fails if the directory exists; existing data is preserved.
(root / "a.txt").write_bytes(b"abc")
(root / "copy.txt").write_bytes(b"abc")
(root / "b.txt").write_bytes(b"xy")

report = inventory(root, hash_contents=True)
assert report["status"] == "COMPLETE"
assert report["file_count"] == 3
assert report["logical_bytes"] == 8
assert report["duplicate_groups"][0]["paths"] == ["a.txt", "copy.txt"]
print(report["logical_bytes"], report["duplicate_groups"][0]["paths"])

The independent hand calculation is 3 + 3 + 2 = 8 bytes across three regular-file paths. The identical abc inputs form one candidate group; xy does not belong to it. The answer printed is:

8 ['a.txt', 'copy.txt']

The CLI exits with 0 for a complete inventory, 1 for a partial inventory and 2 for invalid command-line input. These are interface conventions, not engineering acceptance limits.

Known limits and follow-up

Logical bytes are file lengths per path, not allocated disk usage or recoverable storage. Hard links are counted per name. Sparse files, compression, deduplication, permissions, ownership and retention obligations are not evaluated. A digest match does not authorize removal of either file.

The scan requires a trusted, quiescent input tree and is not an atomic snapshot or a security boundary against concurrent path replacement. Device, inode, length and modification/change timestamps are compared before and after each hash to detect observed changes; changes after a file is read, restored metadata, new files during traversal and changes to directory ancestry can escape detection. Content reads can update filesystem access times.

Metadata is retained in memory in proportion to file count; contents are streamed. Hashing reads all regular files, so its duration depends on input volume. Machine setup, canonical data ownership, backup verification and migration acceptance remain unspecified in issue 33 and require maintainer criteria.
