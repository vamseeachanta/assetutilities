YAML splitting and plotting example

Summary

A mapping is split into independently readable section files, and supplied arrays are plotted with the packaged X-Y template. Comments and quoted keys are retained by round-trip serialization. Compact row formatting changes sequence style without changing scalar values. The example contains synthetic, dimensionless values; no engineering qualification is established.

Method

  1. Parse the original UTF-8 YAML as one mapping. Literal percent signs, blank lines and document-marker text inside strings remain data.
  2. Select each collection or block-scalar section. Single-line scalars such as label are omitted by default. Set single_line_keys_skipped=False to emit them.
  3. Validate every selected key and destination before writing. Filenames have the form <input_stem>_<key>.yml, in input key order.
  4. Copy the round-trip mapping metadata into each section. With shape_output=True, nested two-scalar rows use flow style; longer rows and block-scalar text are preserved.
  5. Pass the supplied curve.x and curve.y arrays to plot_xy_from_arrays. The packaged visualization template supplies plot settings; no test fixture or solver application is required.

Run

From a checkout with the package dependencies installed, select an external output directory. The example script does not modify the input.

python examples/yaml_split_plot/split_and_plot.py \
  examples/yaml_split_plot/input.yml "$OUTPUT_DIR"

The program is split_and_plot.py. The expected outputs are:

sections/input_curve.yml
sections/input_coordinates.yml
Plot/curve.png

The first section contains x: [0, 1, 2, 3] and y: [0, 1, 4, 9]. The second contains the four corresponding pairs, including - [2, 4]. There is no input_label.yml under the default scalar-selection policy. The PNG shows the supplied curve.

The return value remains a list of {"data": path} mappings. The engine's RuamelYAML entry point uses the same splitter. The plot helper accepts a custom template_path and supports plt_engine="plotly" for HTML output.

Limits and failure handling

Empty input, non-mapping roots, duplicate mapping keys, malformed YAML, non-string selected keys, filename separators and case-insensitive filename collisions are rejected. Document streams are not split. Existing destination files are overwritten. Validation precedes output creation, but filesystem failures during writing are not transactional. Comment placement and indentation may be normalized by the serializer; byte-for-byte reproduction is not promised.

Invalid unquoted percent placeholders are no longer repaired during splitting; quote literal strings in the input. Solver application opening, installation and model validation require a separate integration and are not evaluated here.

Verification basis

Regression tests compare parsed section outputs with literal input values, exercise malformed and conflicting inputs, check compact rows and comments, and run plotting from a package layout without repository fixtures. The worked example checks both section contents against Table 2 and checks PNG creation.
