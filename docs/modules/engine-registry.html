Engine runner registry

The engine resolves a configuration basename to a registered class, constructs a new instance, and calls run(cfg). Registration follows the existing ReportWriterRegistry pattern. Unregistered names still enter the legacy dispatch branches.

Extension contract

from assetutilities.engine_registry import EngineRunner, register_runner

@register_runner("uppercase_example")
class UppercaseRunner(EngineRunner):
    def run(self, cfg):
        cfg["answer"] = cfg["text"].upper()
        return cfg

Import the extension module once during application startup, before invoking the engine. Names are exact and case-sensitive. The decorator accepts additional names as aliases. Empty names, repeated aliases, duplicate registrations and abstract or unrelated classes are rejected. Registration of aliases is atomic: a conflict leaves all new names unregistered. The runner constructor must accept no arguments, and run must return the configuration to save.

Registration is explicit trusted Python code. YAML cannot select arbitrary import paths. Registered runners take precedence over legacy handlers; choose a new basename for extensions. Built-in registered names cannot be replaced. Register during startup, before concurrent dispatch. No plugin discovery, unregistration or hot-reload mechanism is provided.

Table: migrated workflows and their original return conventions.

Handler imports remain lazy. Handler and constructor errors propagate; they never trigger legacy fallback. Existing configuration preparation, basename/meta selection, logging, embedding, save behavior, unknown-name errors and explicit stub errors are retained. This migration changes dispatch, not PDF or ZIP algorithms.

Worked example: inputs, method and answer

The executable example is examples/engine_registry.py. With the package installed, run it from the repository root, selecting an output directory:

python examples/engine_registry.py --output example-output

Input: basename uppercase_example, text alpha beta. Method: construct the registered runner, uppercase each letter, preserve the space, return cfg, and save through the engine. Answer: ALPHA BETA, printed and retained in the saved YAML beneath the selected output directory. Embedding preserves the caller's custom fields without requiring a packaged base configuration.

No engineering equation, coefficient or acceptance limit is introduced. The expected text is derived character by character in the example test.
