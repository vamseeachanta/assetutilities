1 Executive Summary

The units module is a quantity-conversion and calculation-history library. Analysis is performed to determine how its public interfaces support unit-aware calculations, and the key results are summarized below.

  • Explicitly labelled quantities can be converted and multiplied while their operation history is preserved.
    • The public pressure–area example gives 405.3 kN for 101.325 kPa acting uniformly over 4.0 m². This is a surface-force magnitude; an allowable load and opposing pressure are not supplied, so capacity and net force are not evaluated.
  • The module can support the numerical part of a calculation record.
    • The source label and operation history do not establish measurement quality or physical validity. Raw numeric inputs at decorated interfaces bypass unit conversion, as described in Section 7.

2 Introduction

The scope and intended use of the quantity workflow are described here. The module is used to attach units to magnitudes, convert compatible quantities and record arithmetic history.

The main workflow covers explicit input quantities, dimensional checking, conversion, multiplication and an audit export. Its public entry points are documented in the repository guide, identified in Section 9.2. The result can be passed to a separate engineering assessment once the physical basis and acceptance criterion are supplied.

2.1 Not covered

The additional sub-areas are identified without extending the worked-example conclusion to them. Commodity-energy adapters, environmental-data adapters, offshore field mappings, automatic input inference, display templates, policy enforcement and lineage rendering are not evaluated as engineering models in this report.

Their interfaces and existing tests are listed in Section 9.2. External integrations are outside the assessed workflow.

3 Summary of Results

The surface-force magnitude at constant example pressure is presented against loaded area. Each point is calculated by calling the quantity interface; intermediate areas are illustrative samples between the origin and the documented example area.

The public pressure–area example gives 405.3 kN for 101.325 kPa acting uniformly over 4.0 m². This is a surface-force magnitude; an allowable load and opposing pressure are not supplied, so capacity and net force are not evaluated.

The legend is defined as follows: “not evaluated” means that a required physical input or criterion is absent; “illustration” means that a teaching input is used without a measurement claim. No allowable-load line is drawn because no numerical limit is available.

4 Basis and Criteria

The arithmetic basis and comparison criteria are defined in this section. The public guide supplies teaching inputs; the external references supply the physical relation and decimal unit definitions.

4.1 Theory and equations

Compatible multiplicative units are converted by equating the same physical quantity in source and target units. With magnitude x and scale c relative to a common unit, the numerical conversion is xtarget = xsource csource / ctarget. This is the factor method described in Reference 1, Appendix B.3; offset temperature conversions are outside this equation.

1 kPa = 1000 Pa; 1 kN = 1000 N; 1 mm = 0.001 m.

The decimal prefixes are defined in Reference 2, Section 4.3, Table 5. Pressure is normal force per area, so the force on a uniformly loaded planar surface is expressed below.

F = p A; Pa × m² = N.

F is normal surface-force magnitude, p is uniform pressure and A is loaded area. The relation is rearranged from Reference 3, Section 14.1, Equation 14.3; the pascal is expressed as newtons per square metre in Reference 2, Section 4.2.1, Table 3.

4.2 Physical and numerical criteria

Uniform pressure over the stated area is an idealization marked ASSUMED - to be confirmed for any physical application. The example inputs are used as specified teaching magnitudes, without assigning measurement uncertainty or material properties.

The report's arithmetic criterion is agreement with the hand-calculated anchors to a relative tolerance of 10−12. This is a numerical regression criterion selected in the report tests, identified in Section 9.2; it is not a material, load or operating limit. Displayed inputs are also multiplied to check the displayed headline result.

Capacity remains NOT_EVALUATED until the allowable load and its governing criterion are supplied. Net force remains NOT_EVALUATED until the pressure on the opposing face is supplied. These dispositions are recorded in Appendix A.

5 Methodology and Interfaces

The quantity interface is applied from explicitly labelled inputs to a force output and calculation record. Pint 0.25.2 and NumPy 2.3.3 are the installed calculation dependencies represented by this copy.

5.1 Inputs and execution

A numeric scalar or array, a unit expression and an optional source label are accepted by TrackedQuantity(value, unit, source). The pressure, area and thickness magnitudes below are read from the public guide rather than duplicated as report constants.

pressure = TrackedQuantity(pressure_value, "kPa", source="Public guide")
area = TrackedQuantity(area_value, "m**2", source="Public guide")
pressure.check_dimensions("Pa")
force = (pressure.to("Pa") * area).to("kN")
audit = CalculationAuditLog()
audit.add_input("pressure", pressure)
audit.add_input("area", area)
audit.add_step("Convert pressure, multiply by area, convert force.")
audit.add_output("force", force)
record = audit.to_dict()

The conversion returns a new quantity with its prior history and a conversion entry. Multiplication combines the operand histories and adds the arithmetic operation; the original inputs remain available. The dimensional check establishes compatibility with a pressure unit, without validating its physical origin.

5.2 Outputs

The outputs are a numeric magnitude, its canonical unit and an operation history. Dictionary serialization includes source labels, operation labels and timestamps; the audit interface groups named inputs, outputs and descriptive steps.

In this report's embedded calculation record, volatile timestamps are omitted while the source, operation and unit fields are preserved. The audit description is supplied by the caller; it is not an executed-equation certificate. The source files and their content digests are listed in Section 9.2.

6 Worked example

The guide's explicit pressure and area are multiplied through the public interface. An explicit conversion is applied to make the force unit unambiguous.

The inputs are 101.325 kPa and 4.0 m². The converted pressure is 101325 Pa. The resulting surface force is 405300 N, expressed as 405.3 kN.

A separate length conversion from the same guide converts 25.0 mm to 0.025 m. That thickness is not used as a structural property of the loaded surface.

The public teaching inputs and their arithmetic locations are identified in the repository record. The physical assumptions and unavailable capacity inputs are recorded in the data register.

7 Limits of Use

The result boundaries are stated here; the associated evidence and handling actions are given in Appendix A. Dimensional compatibility alone does not establish load origin, sign convention, pressure datum, material resistance or uncertainty.

Raw numeric arguments at decorated interfaces remain raw; unknown inferred fields and unknown policy quantity types can pass through. The strict policy flag rejects a mismatched unit only when automatic conversion is also disabled. Required inputs therefore need explicit type, unit and physical checks at the calling boundary.

Custom commodity definitions encode energy equivalents without a published basis in the inspected definition file. Their absolute factors are not evaluated here. The environmental length alias nm denotes a nautical mile in its adapter but a nanometre in the main registry; unambiguous unit names are required.

Provenance records are caller-labelled and mutable through serialization. The lineage rendering connects recorded inputs and outputs without reconstructing exact dependency paths. These records are calculation aids, without tamper evidence or proof of measurement origin.

8 Recommendations

The actions below are tied to the physical and interface limitations identified in this report. No structural acceptance is assigned to the example force.

  • Use explicit quantities and target units at calculation boundaries.
    • Reject missing or untracked required inputs, and distinguish force from pressure before arithmetic, using the dimensional relation in Section 4 and the public interface in Section 5.
  • Supply the physical acceptance basis before applying the surface force to a component.
    • Define the pressure datum, opposing pressure, loaded geometry, allowable load and governing criterion. Confirm the uniform-pressure idealization against the intended loading, as required by the relation in Reference 3.
  • Bound the additional interfaces before wider use.
    • Use full length-unit names in shared data, document commodity-factor sources before absolute energy comparisons, and specify both policy switches when rejection is required. These actions address the inspected behaviours listed in Appendix A.

10 Acronyms and Symbols

The quantities and abbreviations used in the report are defined here. Their units refer to the selected pressure–area example.

F denotes normal surface force in newtons or kilonewtons; p denotes uniform pressure in pascals or kilopascals; A denotes loaded area in square metres. x denotes numerical magnitude and c denotes a multiplicative unit scale relative to a common reference.

SI denotes the International System of Units. NIST denotes the National Institute of Standards and Technology. Pa, kPa, N, kN, m and mm denote pascal, kilopascal, newton, kilonewton, metre and millimetre. JSON denotes JavaScript Object Notation; CSV denotes comma-separated values. SHA-256 denotes the content-digest algorithm used in the source record. NOT_EVALUATED means that the required basis is absent; ASSUMED - to be confirmed identifies an idealization requiring physical confirmation.

Input inference only traverses a flat dictionary and recognizes exact field names; it does not read a configuration file. Explicit units take precedence, unknown fields remain unchanged, and array inputs are outside the scalar inference path. The offshore field dictionary does not automatically extend that parser.

The policy implementation only rejects a mismatched known quantity when strict mode is enabled and automatic conversion is disabled. Both switches need to be specified for rejection. An unknown quantity type passes through. The formatter's direct precision argument is superseded by its resolved template; an explicit template is the documented control.

Energy adapters use literal mapping keys and can reject dimensionally incompatible pairs. Some gas-labelled registry aliases are defined as energy equivalents rather than physical gas volumes. Published commodity-factor metadata is absent in the inspected registry; numerical commodity coefficients are excluded from this report.

Array and offset-temperature behaviour, cross-registry operations, input finiteness, uncertainty propagation, tamper evidence and dependency-graph accuracy are outside the numerical example. Domain adapters return plain magnitudes; the missing-value path in the environmental adapter returns no quantity. These interfaces require their own application-specific input checks.

Appendix B Validation and Quality Evidence

The repository evidence and the new numerical checks are distinguished here. Software checks establish the behaviours they assert; field agreement and a complete engineering qualification are not established.

The existing registry and quantity tests assert compatible conversions, arithmetic and incompatible addition. The integration tests exercise configuration parsing, unit policy, round trips, audit serialization, formatting and lineage construction. A round trip is a consistency check; reciprocal conversion errors can cancel. No saved measured benchmark dataset for the selected pressure–area example is identified in these records.

The report adds hand-calculated pressure, force and length anchors using the external theory in Section 4. The arithmetic is written above each assertion. Separate consistency checks compare every worked-example value and curve point with a fresh module call, and the displayed inputs are multiplied to recover the headline result.

The rebuild check compares rounded payload values with tolerance and compares the remaining document text with the committed copy. Dependency versions are retained in the calculation record and displayed provenance, but are excluded from rebuild equality so supported environments can be compared. Calculation-source digest differences identify stale evidence and name the rebuild command. UTF-8 and line-feed output are checked, and the report tests are exercised with the Python UTF-8 override unset.

The delivery checks cover section structure, local pointers, standalone assets, public wording and the comment-save logic. Browser-rendered layout, measured operating data and licensed integration behaviour are not evaluated by these checks.

Quality pre-flight evidence is held by the report tests in Section 9.2: the inputs have public source locations, the equations have external references, missing physical criteria remain explicit, the summary preserves the surface-force qualifier, and numerical outputs are rebuilt from module calls. Reviewer comments are exported as a separate local JSON file; they are not sent to a service.
