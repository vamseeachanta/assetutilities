1 Executive Summary

The constants module is a scalar conversion and engineering property library. Analysis is performed to determine how its public conversion functions support explicit unit changes; the key results are summarized below.

  • The published length example can be evaluated through the public interface.
    • For 36 ft, the calculated value is 10.9728 m and the rounded presentation is 11.0 m. The latter follows the source example; measurement precision is not inferred by the module. The source is identified in Reference 1.
  • The conversion evidence supports an arithmetic check within the stated numerical tolerance.
    • A physical acceptance limit is not supplied by unit conversion. Material selection, seawater model accuracy and site design conditions remain outside this conclusion, as described in Section 8.

2 Introduction

The module scope is described through its public functions, scalar constants and property records. A complete length conversion is followed from the documented input to a target-unit result and an arithmetic return check.

Pressure, length, force, mass and temperature conversions are supplied as separate scalar functions. Surface seawater density and viscosity functions are supplied alongside steel and casing records. Function docstrings and existing tests establish a public entry point and test coverage; a readiness-only report is therefore not used. The records are listed in Section 9.2.

2.1 Not covered

The main conclusion is limited to the length workflow and the supplementary unit-identity checks. Force, mass, offset-temperature and reciprocal pressure-factor accuracy are not newly benchmarked here. Seawater correlations, hydrostatic modelling, scalar material properties, grade-table accuracy and indicative environmental values are not assessed as design methods.

Their repository tests are included in the existing evidence selection, with the distinction between regression expectations and external validation preserved. No structural model, material allowable or operating envelope is established by this report.

4 Basis and Criteria

The conversion basis is taken from an open metrology guide. Numerical comparison criteria are selected for arithmetic regression and are separated from physical acceptance criteria.

4.1 Theory and equations

A multiplicative conversion is written as y = cx, where x is the magnitude in the source unit, y is the magnitude in the target unit and c is the target-unit magnitude per source unit. This is the factor method in Reference 1, Appendix B.3. The equation applies to compatible multiplicative units; offset temperatures require a different relation.

lm = lft × 0.3048 m/ft.

The symbols lm and lft denote the same length expressed in metres and international feet. The factor is read from Reference 1, Appendix B.8, foot entry. A survey-foot definition is not substituted. The inverse conversion divides by the same factor and provides a consistency check, rather than a separate reference measurement.

For the supplementary inch and bar checks, the cited definitions are combined with decimal prefixes. Their arithmetic is lmm = lin × cm/in / cm/mm and pMPa = pbar × cPa/bar / cPa/MPa. Here p denotes pressure and each c carries the units indicated by its subscript. The factors are given in Reference 1, Appendix B.8 and Section 4.3, Table 5 and reproduced with locators in Table A1.

4.2 Comparison criteria

The hand-calculated anchors are compared with an absolute tolerance of 10−12 in their respective output units. Rounded chart payloads are compared with a tolerance of 10−10 m. These are report-test criteria selected to detect changed arithmetic while allowing binary floating-point rounding; the tests are identified in Section 9.2.

The unrounded length is retained in the calculation payload. Its rounded display follows Reference 1, Appendix B.7.2. The additional arithmetic digits do not establish measurement precision. Finite numeric input is ASSUMED - to be confirmed at the calling interface, because the conversion functions do not enforce an input-validation policy.

5 Methodology and Interfaces

The conversion sequence is performed using the public scalar functions. Input units are selected by the function name and are not attached to the returned number.

A length magnitude in feet is supplied to ft_to_m, and a magnitude in metres is returned. The result is supplied to m_to_ft for a consistency check. The functions inch_to_mm and bar_to_mpa are called with supplementary unit inputs. No dimensional object or uncertainty record is returned.

The wider interfaces are summarized in Table A2. Steel lookup returns a frozen record or a missing result; the surrounding registry remains mutable. Casing records store strength in megapascals, whereas steel records store strength in pascals. The physical-property interfaces do not use the unit-conversion workflow to select a design basis.

6 Worked Example

The published rounding example is evaluated through the module. Its input and reference presentation are read from the source register, and every result below is inserted from a function call.

The input is 36 ft. Calling ft_to_m gives 10.9728 m. The cited factor is 0.3048 m/ft, so multiplication of the displayed input by the displayed factor reproduces the calculated result. The presentation 11.0 m follows the published example in Reference 1, Appendix B.7.2.

Calling m_to_ft with the calculated metre value returns 36 ft. This is a consistency check through the reciprocal implementation. It is not evidence of a separate physical measurement.

The supplementary length input 1 in gives 25.4 mm through inch_to_mm. The supplementary pressure input 1 bar gives 0.1 MPa through bar_to_mpa. These are selected unit-identity checks based on Reference 1, Appendix B.8 and Section 4.3, Table 5, rather than additional published measurement examples.

The hand arithmetic for these results is written above the test assertions. Consistency checks compare the reported outputs and chart samples with fresh calls of the public functions. The displayed headline is also recomputed from its displayed input and cited factor, with no extra input precision supplied.

7 Validation Evidence

The existing repository evidence is separated from the new report checks. Test counts describe execution or source inventory only, rather than engineering acceptance.

The existing constants-related selection contains 126 test definitions across the files listed in Section 9.2. The selection was executed with all cases passing; its shared casing file also includes pipe-geometry tests outside this module. The exact inventory is given in Table A3.

The existing tests check stored constants, conversion round trips, reference expectations, ordering and frozen records. The seawater tests include approximate reference comments, qualitative trends, physical-range checks and a kinematic-viscosity identity. These tests provide regression evidence; their comments alone do not establish agreement with a newly opened scientific dataset.

The new report checks exercise the hand-calculated anchors, fresh-call consistency, displayed precision, offline rebuilding, source links and text encoding. The length example is compared with the opened metrology source. No separately stored field campaign, laboratory benchmark dataset or material certificate is added. A repository-wide test result is not claimed.

The arithmetic evidence does not reconcile parallel material values. A disagreement between the scalar and registry representations of the higher-strength pipeline grade remains in the source; both existing isolated test expectations reflect their respective representation. The implementation records are identified in Section 9.2. No licensed standard value is reproduced here.

8 Limits and Recommendations

The limits of use are defined by the arithmetic interface and available source evidence. Recommendations are tied to the documented behaviour and open-source conversion guidance.

8.1 Limits of use

Unit labels, dimensional compatibility, finite-input checks, measurement uncertainty and physically admissible signs are not enforced by the conversion helpers. Incorrectly labelled inputs therefore remain a caller risk. The pressure reciprocal is stored with finite decimal precision; the scope of the exact-definition example is not extended to every pressure route.

The seawater functions describe a surface-pressure envelope, while hydrostatic pressure uses a fixed nominal density. Input bounds are documented without runtime guards. Correlation accuracy and numerical validity outside the documented envelope remain NOT_EVALUATED here. Numerical envelope values are not adopted as operating limits because the cited scientific source has not been opened for this report.

Material records and environmental scalars are not a substitute for a supplied material specification or site basis. Record immutability does not prevent registry mutation. A missing steel key returns no record, so a result check is required before field access. The scientific attribution and grade consistency concerns in the repository pack remain unresolved by this documentation.

8.2 Recommendations

For immediate conversion use, explicit source and target units are to be recorded at the calling interface and finite inputs are to be checked before arithmetic. Rounding is to be selected for the actual measurement precision and intended use, following Reference 1, Sections 7.9 and B.7.2. The unrounded value is to be preserved for subsequent calculations.

Before either parallel grade representation is used for material selection, the maintainer is to reconcile its basis against the applicable specification and add a cross-representation assertion. Before seawater outputs are used in an engineering assessment, the applicable correlation, pressure convention and source envelope are to be established and checked at the interface. These actions follow the implementation gaps documented in Section 9.2; design acceptance remains NOT_EVALUATED until that evidence is supplied.

The next numerical slice is a cited pressure-conversion benchmark followed by a separately sourced seawater-property assessment. The existing functions and tests provide the interface inventory for that work; no conclusion from the length example is transferred to those physical models.

10.3 Quality pre-flight evidence

The report checks compare hand-calculated literals with module results, compare fresh module calls with the worked example and chart payload, recompute the displayed headline and rebuild into a separate directory. Numeric payloads are compared with stated tolerances before they are masked for the remaining document comparison. Source changes or stale counts identify the rebuild command in the failure message.

Text files use explicit UTF-8 decoding and LF writes. The report tests are executed with the Python UTF-8 environment switch unset. Internal links, section count, standalone assets and source-register locators are checked. Interactive browser behaviour and the complete repository suite are not executed as part of this report assessment.
