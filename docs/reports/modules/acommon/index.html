Common module: data transformation analysis

Draft for maintainer review

1 Executive Summary

The common module is a collection of shared configuration, data, file and presentation utilities. Analysis is performed to determine how a sourced length conversion is applied by its data-transformation interfaces; key results are summarized below.

  • Length values are converted using an explicit international-foot basis.
    • The published input of 36 ft returns 10.9728 m before reporting precision is applied. The reported result is 11.0 m under the rounding treatment in Reference 1, B.7.2.
  • Data handling is selected according to the required mutation behaviour.
    • The DataFrame route returns a copy; the scalar and list route replaces data in the supplied configuration. Neither route applies a physical acceptance limit or checks the unit basis.

2 Introduction

The common module is used to support application inputs, data preparation and output production. The selected workflow is bounded to numerical scaling and record export, with the surrounding utilities listed separately.

A full report is provided because callable interfaces and existing tests are present. Public usage is documented for the validation class and structured-report functions; the numerical transformation contract is described here and is exercised by existing tests. This report assesses a data operation, rather than installation feasibility or structural performance.

2.1 Workflow and interfaces

Input values and conversion settings are supplied by the caller. The output unit is attached by the caller after conversion.

The scalar and list entry point is TransformData.linear(cfg), which returns the supplied dictionary after replacing data. Its keys are data, scale and shift. The DataFrame entry point is Transform.get_transformed_df(settings, frame); each setting supplies column, scale and shift. Record export is provided by dataframe_to_dict(frame, {"orient": "records"}), returning a list of row dictionaries for this orientation.

3 Design Data and Criteria

The international foot is adopted from Reference 1, B.8. The published example and its rounding interval are taken from Reference 1, B.7.2.

The input is 36 ft; the exact conversion scale is 0.3048 m/ft. The selected shift is 0 m because length conversion preserves the origin. The source discusses inputs from 35.5 to 36.5 ft as a rounding interval; the endpoints are displayed as bounds, without assigning a probability distribution.

No structural, thermal, operational or instrument limit is specified. Acceptance for this example is numerical agreement at displayed precision with the public conversion and agreement among the called interfaces. The rounding bounds are not acceptance limits. Measurement uncertainty is not estimated from these bounds.

4 Analysis Methodology

An affine transformation is applied to each selected value. The scaling interpretation follows Reference 1, B.3; an offset conversion is illustrated there by the Celsius relation in 4.2.1.1, but no temperature calculation is assessed here.

y = a x + b, where x is the input numerical value in ft, y is the output numerical value in m, a is the scale in m/ft and b is the shift in m. For the selected length conversion, y = 0.3048 x + 0 (Reference 1, B.3 and B.8).

The same source inputs are passed to scalar, list and DataFrame calls. The DataFrame is then exported as row records. The public reporting precision is applied separately from the transformation. Intermediate arithmetic is displayed to preserve the exact converted values for the stated decimal inputs; it does not imply measurement precision.

4.1 Executable use

The following call is made in the report generator. The source dictionary is replaced in place by the scalar result.

from assetutilities.common.transform import TransformData
cfg = {"data": 36, "scale": 0.3048, "shift": 0}
result = TransformData().linear(cfg)
length_m = result["data"]

5 Detailed Results

The scalar conversion returns 10.9728 m. The reported measurement is 11.0 m, following Reference 1, B.7.2, and is kept separate from the arithmetic result.

The converted rounding bounds are 10.8204 m and 11.1252 m. All displayed results, bounds and plot ordinates are produced by module calls. The per-case values are listed in Appendix A.1.

6 Validation Evidence

Existing transformation tests are held in the repository. Their selected inventory contains 5 tests across scalar, list and DataFrame behaviour; the inventory is not a statement about whole-module coverage.

The existing assertions cover scale and shift, an absent target column and preservation of the original DataFrame. The added report checks compare each generated value with fresh module calls and include hand-worked anchors at both rounding bounds and the published central input. These comparisons establish the example calculation and the interfaces exercised; they do not qualify unrelated utilities.

The published example is a numerical reference, not experimental benchmark data. No physical benchmark dataset is used in this report. An execution record is provided in Appendix A.3.

7 Limits of Use

Unit selection and data validity are delegated to the caller. Missing target columns are silently skipped by the DataFrame transformation.

The scalar and list route mutates the configuration; repeat application converts already converted data again. Its dispatch wrapper mutates the input and returns no result. The list branch requires an actual list; tuples and arrays are not assessed by this example. The DataFrame route copies its input and preserves the target column name, so the caller is responsible for labelling the output unit. Multiple settings for the same column are applied in sequence.

No finite-number, unit-dimension, uncertainty or engineering acceptance check is performed by these transformation methods. Generic scale and shift settings are not a replacement for a unit registry. Record export requires unambiguous column names; duplicate names return an empty dictionary in the inspected implementation.

7.1 Not covered

Configuration merging, path resolution, file copying and editing, spreadsheet and document operations, database access, web retrieval, validation scoring, logging, plotting and geographic conversion are outside the assessed workflow. Their presence is established by source inventory, without asserting their readiness.

Interpolation and inverse geographic conversion contain unimplemented methods in the transformation source. The CSV reader wrapper returns an undefined name in the inspected source. These interfaces are excluded from the example; the documented structured-report entry point is present but is not called here.

8 Recommendations

Explicit unit and column checks are recommended before transformation. The method is selected according to whether configuration mutation is intended.

Use the exact international-foot conversion only when that input basis is established, and apply reporting precision after the arithmetic (Reference 1, B.7.2 and B.8). Preserve the original readings and write the output unit alongside the converted data. Reject absent target columns before the DataFrame call, because the implementation skips them.

The next bounded extension is a checked transformation adapter with declared input units, output units and required columns. Its first acceptance cases are a missing column, a non-finite value and repeated conversion. For the excluded CSV wrapper, return-value repair and a file-reading test are recommended before adoption; the interpolation and inverse-geographic placeholders require implemented behaviour and tests before use.

No failing physical result is reported. Numerical agreement is limited to the selected reference and calls; engineering limits require a separate, sourced acceptance basis.

9 References

The conversion basis is taken from an open institutional publication. Repository records identify interfaces and test assertions rather than establish physical conversion factors.

9.1 Published reference

Reference 1. NIST Special Publication 811, Guide for the Use of the International System of Units, 2008 edition: 4.2.1.1 (temperature offset relation), B.3 (conversion-factor use), B.7.2 (rounding converted values, published length example), and B.8 (international-foot conversion). Open publication. The conversion clauses are used; the publication's historical definitions of base units are not adopted as current definitions.

10 Acronyms and Symbols

Symbols are defined for the selected length transformation. No domain-specific shorthand is required to interpret the result.

x: input numerical length in ft; y: output numerical length in m; a: scale in m/ft; b: shift in m. The symbol ft denotes the international foot; m denotes the metre. A DataFrame is a labelled table, and a record is a row represented as a dictionary.
